# AIS-catcher Frontend Revamp — Specification

## Context

AIS-catcher is a C++ SDR-based AIS receiver with a built-in HTTP/WebSocket server.
The frontend lives in `Source/HTML/` and is baked into the binary at build time via
`WebDB.cpp` (generated by `scripts/build-web-db.sh`).  No build tooling, no modules,
no bundler — `script.js` is a 296 KB monolith.

## What This Revamp Covers

| Scope | In scope | Out of scope |
|---|---|---|
| `Source/HTML/` files | ✅ Frontend source | ❌ C++ backend |
| CI/CD | ✅ GitHub Actions | ❌ AppVeyor/vcpkg |
| Docker | ✅ New frontend-dev image | ❌ Existing prod Dockerfile |
| Map engine | OL 10 → MapLibre (future) | ❌ Not in this spec |
| Plugin system | ✅ Extension points | ❌ New plugin API |

## Architecture

```
Source/HTML/               Source/HTML/dist/              WebDB.cpp
  index.html  ──Vite──►   dist/index.html  ──build-──►  embedded
  script.js               dist/bundle.[hash].js     at build time
  style.css               dist/bundle.[hash].css
  ...                     dist/chart.[hash].js
                          dist/ol.[hash].js
                          dist/tabulator.[hash].js
```

### Build pipeline (Vite + bakeHTML CI job)

1. `npm run build` — Vite bundles Source/HTML/src/ → Source/HTML/dist/
2. `build-html.sh` — hashes the dist filenames into index.html, rewrites CDN links
3. `build-web-db.sh` — bakes Source/HTML/ into WebDB.cpp (unchanged step)
4. GitHub Actions `bakeHTML` job commits WebDB.cpp (unchanged step)

The CI `bakeHTML` job is **unchanged** except for adding Node.js setup.
CMake is **unchanged** — it just compiles WebDB.cpp as before.

### Docker strategy

```
Dockerfile.frontend-dev   (new, purpose-built)
  Stage 1 (build):        node:20 → npm install → vite build
  Stage 2 (runtime):      debian:bookworm-slim + AIS-catcher binary
  Entry:                  AIS-catcher binary + smoke test on :4254 UDP
```

## Testing

### Smoke test (against UDP stream on host:4254)

```bash
# Start AIS-catcher with UDP input
AIS-catcher -u <stream_host> 4254 -N 8100 REALTIME on LOG on DECODER on

# Wait 5s for startup, then run smoke tests
smoke_test.sh
```

**smoke_test.sh validates:**

| Endpoint | Expected |
|---|---|
| `GET /` | 200, HTML with `<div id="map">` |
| `GET /api/stat.json` | 200, valid JSON |
| `GET /api/ships.json` | 200, valid JSON array |
| `GET /api/ships_array.json` | 200, valid JSON array |
| `GET /api/sse` | 200, Content-Type: text/event-stream |
| `GET /api/log` | 200, Content-Type: text/event-stream |
| `GET /api/decode` POST | 200, valid JSON |
| `GET /api/history_full.json` | 200, valid JSON |

### Regression test (frontend visual)

1. Open browser at `http://localhost:8100`
2. Verify map tab shows ship icons / tracks
3. Verify SSE stream updates vessel list
4. Verify settings panel opens/closes
5. Verify NMEA decoder tab decodes a test sentence
6. Toggle dark mode, verify CSS variables apply
